# Bright Boost Internship Program Documentation

This directory is the canonical entry point for planning, operating, or reviewing a Bright Boost internship cohort.

## Required reading order

Before creating a cohort plan, assigning intern work, changing onboarding, or running closeout:

1. Read [OPERATING_STANDARD.md](./OPERATING_STANDARD.md).
2. Read the most recent anonymized lesson record in [`./retrospectives/`](./retrospectives/).
3. Create the new cohort plan from [PROGRAM_PLAN_TEMPLATE.md](./PROGRAM_PLAN_TEMPLATE.md).
4. Check the current repository and product documentation before reusing any technical assumptions from a retrospective.

## Document roles

- **Operating standard:** Year-neutral program requirements. Update deliberately when leadership accepts a lasting policy change.
- **Program-plan template:** Required decisions, owners, dates, and evidence for one cohort.
- **Anonymized lessons:** Historical program observations and the evidence behind later improvements. They do not silently override the operating standard.

## Governance

- **Policy owner:** Bright Bots Initiative Executive Director or delegated program lead
- **Technical owner:** Named technical lead for the cohort
- **Review point:** Before recruiting or assigning work for every new cohort
- **Change rule:** Record the reason, owner, and effective cohort whenever the operating standard changes
- **Privacy rule:** Convert individual difficulties into program improvements. Named closeout notes and recommendation drafts stay in private leadership storage and must not be committed to the public repository.
