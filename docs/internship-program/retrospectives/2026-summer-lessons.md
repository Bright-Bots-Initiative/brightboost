# Summer 2026 Internship Program Lessons

**Visibility:** Public, anonymized program record  
**Recorded:** August 14, 2026  
**Purpose:** Preserve cohort-level learning without publishing individual performance or private closeout details

## What worked

- Authentic collaboration made the program feel more like professional engineering than isolated coursework.
- Slack updates helped participants maintain context as the shared codebase changed.
- Pull-request review exposed participants to other contributors' decisions and workflows.
- Improving existing games and interfaces provided meaningful product constraints and opportunities for user-centered iteration.
- Participants valued learning to use LLMs while retaining human judgment, verification, and responsibility.
- Cross-functional work connected game design, UI/UX, front-end implementation, localization, testing, and architecture.

## What created avoidable friction

- Local requirements were not equally clear before the program began.
- The full Git workflow—from local change through branch, push, pull request, review response, and updated PR—needed more guided practice.
- GitHub notifications alone did not always create a visible, timely handoff.
- Participants wanted more deliberate interaction with one another.
- Localization assignments sometimes lacked enough context or an authoritative reviewer for uncertain wording.
- Portfolio evidence was easier to reconstruct at closeout than it would have been if captured throughout delivery.

## Changes adopted for future planning

1. Hold a recorded group setup huddle before the program begins.
2. Require every participant to pass an environment and Git flight check before receiving production work.
3. Give each participant a primary technical lane and one optional stretch area.
4. Use GitHub as the source of truth and Slack as the attention layer for action-required handoffs.
5. Schedule rotating peer reviews, huddles, and demos rather than relying on spontaneous interaction.
6. Provide an LLM verification and data-safety standard in Week 1.
7. Supply localization context, a glossary, an uncertainty path, and a named language reviewer.
8. Include test cases and expected evidence in every assignment's definition of done.
9. Capture portfolio-safe evidence as each milestone is completed.
10. Collect midpoint feedback early enough to change the active program, followed by individual closeouts and an anonymized final retrospective.
