# Internship and contributor-cohort program rules

Before planning, changing, or closing an internship, fellowship, volunteer engineering cohort, or other contributor program:

1. Read the [program documentation entry point](../../internship-program/README.md) and [operating standard](../../internship-program/OPERATING_STANDARD.md) completely.
2. Read the most recent anonymized lesson record under [`docs/internship-program/retrospectives/`](../../internship-program/retrospectives/).
3. Build the cohort plan from the [program-plan template](../../internship-program/PROGRAM_PLAN_TEMPLATE.md).
4. Treat the operating standard as canonical. Retrospectives preserve evidence and history but do not silently override current policy or repository architecture.
5. Convert individual friction into program-level improvements; do not turn private closeout feedback into public performance scoring.
6. Preserve named owners, dates, required evidence, onboarding readiness, GitHub-plus-Slack review handoffs, responsible LLM guardrails, test cases, and portfolio capture.
7. Never commit named closeout notes, recommendation drafts, health information, or other participant-specific private feedback to the public repository.
