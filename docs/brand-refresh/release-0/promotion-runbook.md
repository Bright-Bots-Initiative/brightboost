# Promotion runbook — staging → production

Production no longer deploys on push. Both production services in the canonical Railway project (`glorious-friendship`, `fd8b32c5-9922-4e93-b9a5-010591716300`) have auto-deploy **disabled** and Wait for CI **enabled** (applied 2026-09-03T17:14Z, evidence register E-33). A release reaches production only through **Deploy promote (exact SHA)** — `.github/workflows/deploy-promote.yml` — whose production job runs under the GitHub `production` environment (required reviewer: team `team-leads`; prevent self-review; protected branches only; no admin bypass). The Railway credential is an environment-scoped secret, so the deployment step cannot obtain it until that approval happens.

## Preconditions

1. The candidate is a commit on `main` — call it `SHA` (full 40 hex). Read it with `git rev-parse origin/main`.
2. Required checks green on `SHA`: `gh api repos/Bright-Bots-Initiative/brightboost/commits/SHA/check-runs --jq '.check_runs[] | "\(.name)\t\(.conclusion)"'` shows `build-and-test`, `db-check`, `e2e-flows` = `success`.
3. Staging carries `SHA` and passes **strict** verification (the promotion job re-proves this itself and refuses otherwise):

```bash
node scripts/verify-deploy-target.mjs --url https://fe-staging-staging-126a.up.railway.app \
  --expect-env staging --expect-sha SHA --require-declared-env --expect-analytics disabled
CYPRESS_SWA_URL=https://fe-staging-staging-126a.up.railway.app VITE_API_BASE=https://fe-staging-staging-126a.up.railway.app npm run test:e2e:staging
```

4. For BRAND_R1 changes only: the visual/functional walkthrough in the evidence register is signed by a second person.
5. No open `P1` defect on the surfaces the change touches.
6. A database backup newer than the last schema change exists (Supabase → Backups; the production series is daily physical backups at ~08:15 UTC).
7. If `SHA` contains a migration (`prisma/migrations/` changed since the live SHA): read it; confirm it is additive or has a rollback note.

Go straight to the [rollback runbook](rollback-runbook.md) with `PREV`. Do not fix forward on production.
